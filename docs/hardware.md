# 真实硬件接入

## 最小硬件组成

| 设备 | 需要满足的条件 |
| --- | --- |
| Linux 主机/开发板 | 可运行 C++17 程序、SQLite 运行库，具备 USB 或 UART 接口 |
| USB-RS485 适配器 | Linux 可识别为 ttyUSB/ttyACM；自动控制 RS485 收发方向 |
| Modbus RTU 温湿度传感器 | 允许读取两个连续输入寄存器，功能码 0x04，数据映射如下 |
| 传感器电源 | 严格按传感器手册提供，避免把 12/24V 接到开发板串口 |

开发板不是必需购买项：先在现有 Linux 电脑完成模拟和 PTY 测试，再选择你能长期使用的板卡。这里不绑定特定厂商。

## 接线

| 适配器侧 | 传感器侧 | 说明 |
| --- | --- | --- |
| RS485 A | RS485 A | A/B 命名在厂商间可能相反，以双方手册为准 |
| RS485 B | RS485 B | 使用双绞线；不能接到 TTL TX/RX |
| 信号参考地 | 信号参考地 | 按电气/隔离方案接线，避免地电位差 |
| 独立合规电源 | 传感器 V+/V- | 按设备电压、电流及极性供电 |

长总线应按现场拓扑评估两端终端电阻、偏置和屏蔽；不要对每个从站都加终端。实际电气设计按设备手册实施。USB-RS485 和 TTL UART 不是可直接互换的电平接口。

## 本工程寄存器约定

| 偏移（0 起始） | 类型 | 解释 | 示例 |
| --- | --- | --- | --- |
| register_start + 0 | 有符号 16 位，大端寄存器 | 温度，单位 0.1°C，范围 -40～125°C | 0x0138 = 31.2°C；0xFFCC = -5.2°C |
| register_start + 1 | 无符号 16 位，大端寄存器 | 湿度，单位 0.1%RH，范围 0～100% | 0x020C = 52.4%RH |

请求示例：`01 04 00 00 00 02 71 CB`。CRC 在 RTU 帧中低字节先发送。设备手册中的 30001、40001 之类展示地址不一定等同于 PDU 的零起始地址，应查明对应关系。

不少传感器采用功能码 0x03、湿度在前、温度在后、32 位浮点或不同缩放系数。**仅修改串口路径不能适配这些设备**：需修改 `src/modbus.cpp` 的 `read_request`、`ModbusDecoder::next`，并补充厂商真实响应帧测试。当前工具模拟 0x04、起始地址 0、两个寄存器。

## 调试步骤

1. 运行 `dmesg`、`ls -l /dev/serial/by-id/` 确认适配器。优先把 `serial_device` 配成稳定的 `/dev/serial/by-id/...` 路径。
2. 确认运行账户能访问设备。Debian 系设备通常归 dialout 组；其他发行版可能使用 uucp 等组。不要用全局 `chmod 777` 代替权限配置。
3. 把 `source` 改为 `modbus`，设置设备地址、波特率、N/E/O 校验、起始寄存器。程序目前固定 8 数据位、1 停止位；设备若要求 2 停止位，需要先扩展串口配置。
4. 在前台启动，观察 `serial_connected` 日志，再查看 `/api/v1/status` 的 acquired、timeouts、crc_errors。
5. 停止传感器/拔下适配器，确认过期状态、重连日志；重新接入后确认 `serial_reconnects` 增加并恢复采集。
6. 用可信温湿度参考仪器检查数值与缩放。测试阈值前先确认监测系统不会控制危险设备。

已有原生 RS485 UART 的板卡可能需要 `TIOCSRS485` 和设备树配置；本工程没有实现该控制路径。可以先使用自动方向控制的 USB 适配器完成应用层验证。

## 现场验收建议

记录目标板型号、系统/内核、传感器型号及固件、串口设置和存储介质。进行至少一个完整运行周期的采样稳定性、拔插、断电重启、磁盘空间、系统校时及长时间运行测试。项目内 PTY 测试无法验证电平、方向切换、RS485 帧间隔、干扰、存储实际掉电行为或温湿度测量准确度。
