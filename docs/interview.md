# 学习与面试讲解

## 这个项目能支撑哪些能力

| 岗位能力 | 对应代码/任务 | 能讲清楚才算掌握 |
| --- | --- | --- |
| C/C++ 基础与资源管理 | fd.hpp、unique_ptr statement、线程生命周期 | move 语义、RAII、构造异常时谁负责清理 |
| Linux 系统编程 | gateway.cpp、serial.cpp | fd、非阻塞、EAGAIN/EINTR、termios、epoll LT |
| 多线程 | queue.hpp、storage.cpp | 条件变量为什么要 predicate，关闭后怎么唤醒与排空 |
| 通信协议 | modbus.cpp、PTY 传感器 | 大端寄存器/小端 CRC、拆包、异常响应、超时 |
| 数据可靠性 | SQLite 事务和 WAL | 原子性与掉电持久性的区别，内存队列会丢什么 |
| 网络应用 | http.cpp、API | 部分收发、请求边界、连接上限、鉴权与 TLS 的区别 |
| 工程化 | CMake、tests、CI、systemd | 交叉编译为何需要 sysroot，服务怎么退出/重启 |
| 排障与验证 | measure.py、日志、故障注入 | 用可复现实验判断瓶颈，不凭感觉报性能数据 |

这是 Linux 用户态应用工程，适合网关、设备通信、数据采集和边缘设备软件方向；不能据此声称掌握内核驱动、BSP、硬实时控制或功能安全认证。

## 从零开始的动手顺序

1. **先跑通**：在 Linux/WSL2 构建、执行测试、用 curl 读取数据。把默认阈值改成 28°C，观察进入与恢复告警的时机。
2. **读懂协议**：手算一组带符号温度寄存器，修改 PTY 传感器让它输出负温度；在解码器中跟踪一帧的每个字节。
3. **理解事件循环**：追踪 timerfd 如何发起请求、EPOLLOUT 如何继续部分写入、EPOLLIN 如何拼装响应；用 strace 观察系统调用。
4. **理解线程边界**：临时把数据库写入变慢，减小队列容量，确认丢弃计数、最新状态与历史数据之间的差别；清除实验改动后提交自己的测试。
5. **上真实硬件**：接一款有明确协议手册的传感器，记录映射改动、设备型号、串口配置和参考仪器比对结果。
6. **做一次完整交付**：独立完成 systemd 安装、重启、日志查看、备份恢复和远程隧道，并把实际命令写进自己的测试记录。

学习节奏按你自己的 C++/Linux 基础调整，不把“看过代码”等同于独立实现或现场交付。

## 建议你亲手完成的三个扩展

- **设备映射可配置**：支持功能码 0x03/0x04、寄存器顺序与比例系数。先加真实帧回归测试，再改协议层。
- **批量持久化**：例如最多 N 条或最多 T ms 一批，记录吞吐与 p95 延迟、断电丢失窗口和写入次数的变化。
- **第二个设备**：设计多从站轮询状态机，解释同一 RS485 总线为何不能让多个请求任意并发，加入某个从站掉线时不阻塞其他设备的测试。

如果后续增加 MQTT，先定义消息 id、设备身份、确认机制、重试与幂等，再做落盘 outbox。仅在连接成功时 publish 不等于实现离线补传。

## 面试时可以演示的五分钟

1. 展示默认模拟数据页面和 API。
2. 切换到 PTY 串口，开启 CRC 错误/丢帧注入，说明 counters 变化。
3. 停止并重新启动传感器，观察设备断开、stale 和重连恢复。
4. 运行 ctest，解释为什么测试不只断言函数结果，还创建真实进程和串口 fd。
5. 展示一次自己的板卡实测记录，讲明 CPU/RSS/延迟的测量条件，以及还没解决的限制。

## 可核实的简历表述

在你已独立理解、修改并能解释代码后，可按真实参与程度填写，例如：

> 嵌入式 Linux 设备采集网关：基于 C++17/POSIX 实现单从站 Modbus RTU 温湿度采集，通过 epoll 管理串口、HTTP 与定时事件，使用有界队列和独立 SQLite 工作线程完成本地存储；实现带滞回的高温告警、超时与串口重连，提供状态接口、监控页面、systemd 部署及自动化故障注入测试。

如果实现了硬件适配，再补充**实际板卡/传感器型号、真实采样率、实测时长和指标**。不要把本地模拟器验证写成量产落地，不要编造“数据零丢失”“毫秒级实时性”“稳定运行半年”等经历。这个初始版本由辅助工具搭建，你后续独立做过的设计、调试与验证才是可展开讲述的个人贡献。

## 常见追问

**为什么不让采集线程直接写 SQLite？** 同步磁盘操作可能延误串口和 HTTP；独立 writer 隔离主要写入延迟，但主线程历史查询仍有延迟上限问题。

**队列满了怎么办？** 丢弃新存储任务并累计计数，最新状态继续更新。这是明确的降级策略，不是零丢失方案。

**WAL 等于掉电不丢数据吗？** FULL 同步强化已提交数据的持久性，仍依赖底层存储；未提交和未入队数据不受此保证。SIGKILL 测试也不等同于物理断电。

**为什么有告警滞回？** 防止温度在高阈值附近小幅变化时反复触发与恢复。

**怎么证明重连有效？** 集成测试销毁旧 PTY，再创建新 PTY 并更新稳定设备链接，断言网关重新打开设备并采集负温度数据；真实 USB/RS485 仍需上板验证。

**为什么不是直接用现成 HTTP 库？** 当前只读 API 范围小，便于展示系统编程；进入需要复杂 HTTP/TLS/高并发的产品应选维护成熟的库，并重新验证。
